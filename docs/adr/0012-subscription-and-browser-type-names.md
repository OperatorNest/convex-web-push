# 0012: Serialized subscription and browser helper type names

The serialized subscription has one name in every entry point: `PushSubscriptionJSON`, the W3C name for the shape `PushSubscription.toJSON()` returns. The client no longer exports a `PushSubscription` type, which shadowed the live W3C interface. The package type deliberately keeps the DOM name because it narrows the DOM `PushSubscriptionJSON`, requiring `endpoint` and `keys`; a module that imports it uses the narrower type under the same name.

The browser permission union, which adds `unsupported` to `NotificationPermission`, is `PushPermission`, returned by `getPushPermission()`, instead of `PermissionState`, which names the Permissions API union; no DOM type is named `PushPermission`. The registration selector is `ServiceWorkerScopeOptions` instead of `RegistrationOptions`, which named the options of `ServiceWorkerContainer.register()`. The service worker parses payloads as `Partial<PushNotification>` instead of a separate `PushPayload` type. The copied classic worker `sw/convex-web-push-sw.js` parses, displays and routes notifications exactly as `registerPushHandlers` does, keeping empty-string payload fields; it reads its defaults from its `DEFAULTS` object because a copied classic worker receives no options argument.

Exported validators are named `<concept>Validator`, for example `pushSubscriptionValidator`, so a validator and the type it checks share one concept word.
